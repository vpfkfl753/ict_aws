# Slack Agent Plane v2 구현·운영

2026-09-21. 개발 기준은 [DEVELOPMENT_SSOT.md](DEVELOPMENT_SSOT.md)다.
이 문서의 기능은 코드·자동 테스트 기준이다. 현재 재용 머신의 운영 서버는 protocol 1이며,
아래 업데이트가 반영되기 전에는 새 승인 화면이나 Home 기능이 활성화되지 않는다.
기존 Kiro 실제 송신 증거와 이번 v2 자동 테스트 결과를 혼동하지 않는다.

## 사용 흐름

```text
사람 DM /tacit-send @상대 메시지
  │
  ├─ 원문 DM 먼저 전송 (이미 전송된 자동 감지 메시지는 재전송 안 함)
  └─ 내 워커
      ├─ 원문 이전 DM 대화 + 허용 폴더 검색 → 모델이 추가 검색·파일 선택 → 맥락 초안
      ├─ 초안·접근 기록은 내 디스크에만 저장
      └─ 원문 DM 안에 나에게만 표시되는 공유 미리보기
           ├─ 취소 → 원문은 유지, 추가 공유 종료
           ├─ 수정·제외 후 승인 → 수정한 본문만 공유
           └─ 승인 → 미리 본 버전만 공유
                 │
                 ▼
             상대 Agent
               ├─ 상대 로컬 자료·DM 대화와 비교 → 원문 DM 안에서 상대에게만 설명
               └─ 부족하면 내 Agent에 질문 (최대 2왕복)
                    ├─ 이미 공유한 정보 → 해당 근거를 인용해 자동 답변
                    └─ 새 정보 필요 → 새 초안과 새 사용자 승인
               여전히 부족하면 원문 DM 안에서 자기 사용자에게 질문 → 그 작업만 대기
```

### DM 안에서 끝내는 흐름

원문 DM(protocol 2, `dm` 모드)에는 두 사람과 Tacit이 함께 있다. 두 사람은 일반 메시지로 대화하고,
Tacit 단계는 각자에게만 보이는 **나에게만 표시** 메시지와 버튼·팝업으로 처리한다.
각 워커가 자기 사용자 토큰으로 `chat.postEphemeral`(user=본인)을 호출해 원문 DM에 직접 게시하므로
승인 전 초안과 확인 질문은 중앙을 거치지 않는다. 수신자 설명은 기존처럼 중앙의 수신자 전용 필드에도 저장한다.

| 사용자 | 원문 DM에 표시 | 버튼·팝업 |
|---|---|---|
| 송신자 | 공유할 배경 미리보기 | 공유 / 수정(팝업) / 공유 안 함 |
| 수신자, 자동 수신 켬 | 나를 위한 설명 전체 | 없음 |
| 수신자, 자동 수신 끔 | 설명이 준비됐어요 | 보기(팝업, 중앙의 내 설명 조회) |
| 수신자 | Agent의 확인 질문 | 답변하기(팝업) |

- Tacit 봇 카드가 먼저 생기기를 기다리지 않는다. Agent 전용 모드는 기존처럼 Tacit 대화에 표시한다.
  Slack이 원문 DM 게시를 거절하면 그 알림만 Tacit 대화 카드 쪽에 대신 표시한다.
- 나에게만 표시 메시지는 새로고침·다른 기기에서 사라진다. 그래서 Tacit 봇 대화의 작업 카드와
  Home을 기록으로 유지한다. 설명은 카드를 짧게 갱신할 뿐 새 메시지로 다시 보내지 않는다.
  승인·질문 대기의 짧은 알림(원문 발췌만 포함)은 놓친 경우를 위해 유지한다.
- 카드의 **내용 확인**을 누르면 미리보기를 그 카드가 있는 Tacit 대화에 다시 표시한다.
- 공유·공유 안 함을 누르면 해당 미리보기를 결과 문구로 바꿔 버튼을 없앤다. 버튼은 소유자·버전·상태를
  다시 확인하므로 처리된 버튼이나 다른 사람의 버튼은 거절한다.
- 같은 알림은 로컬 전송 대기열 파일로 한 번만 게시한다.

Tacit 앱과의 DM에서 `/tacit-send @상대 메시지`를 실행하면 Agent 전용 요청으로 접수한다.
이때 상대 사람 DM에 원문을 보내지 않는다. 상대의 로컬 정보로 만든 답변은 상대 사용자가 승인하면
질문한 사람의 Tacit 대화에 자동으로 돌아온다. `/tacit-send @broadcast 질문`은 등록된 다른
사용자들의 Agent 각각에 작업을 만든다. 각 상대에게 보낼 맥락은 개별 승인한다.
인자를 생략한 전송 창에서도 `원문 DM + 맥락 / Agent끼리 질문 / 모든 Agent에게 질문`을 고른다.
대화 구성원 조회가 실패하거나 대화 정보가 없으면 원문 DM으로 추정하지 않고 접수를 중단한다.
이 경우 인자 없는 `/tacit-send` 창에서 모드를 직접 선택한다.

`/tacit-receive [작업 ID]`는 자신이 참여한 작업을 본인에게만 보이는 응답으로 조회한다.
자동 수신을 꺼도 조회할 수 있으며, Agent 전용 요청 결과는 자동으로 알려준다.

## Slack에서 설정·기록 보기

- Tacit **Home**: 자료 폴더, 실행기, 모델, 웹 검색, 대화 기록 참고, 자동 수신, DM 자동 준비, 최근 작업.
- **기록**: 승인한 맥락, Agent 질문·답변, 승인·취소·실패 등 작업 이력.
- **내 로컬 접근·도구 기록 받기**: 내 워커가 최근 접근·검색 기록을 내 Tacit 대화로 직접 전송.
- 작업별 봇 스레드: 양쪽에 공유된 맥락과 Agent 대화·상태를 순서대로 표시.
- 승인 미리보기, 사용자 확인 질문, DM 모드의 수신자 설명: 로컬 워커가 자신의 사용자 토큰으로
  DM 모드는 원문 DM에, Agent 전용 모드는 Tacit 앱과의 대화에 직접 게시한다.
  봇이 쓴 메시지처럼 위장하지 않으며, 사용자 작성자로 표시될 수 있다.

Home에 입력한 폴더는 로컬의 `TACIT_ALLOWED_ROOTS`를 넘어설 수 없다.
이 값은 머신에서만 바꿀 수 있으며, 생략하면 기존 `TACIT_WORKSPACE`만 허용한다.
빈 실행기·모델 설정은 기존 로컬 워커의 설정을 사용한다. 계정 로그인은 각 머신에서 한다.

```dotenv
# 이 개발 머신에서 허용하는 범위. 실제 연구 폴더는 포함하지 않는다.
TACIT_ALLOWED_ROOTS=/home/user/work/ict_aws/examples:/home/user/work/ict_aws/demo
```

DM 자동 준비는 **기본 꺼짐**이다. Slack이 해당 설치·사용자 권한으로 전달하는 신규 1:1 DM
이벤트만 처리한다. 등록된 두 참여자, 일반 메시지, 자동 준비를 켠 송신자만 대상이다.
스레드 답변·봇 메시지·앱이 게시한 원문은 제외한다. 앱이 접근하지 못하는 DM은 읽지 못한다.
자동 준비를 켜도 **추가 맥락 공유 승인은 생략하지 않는다**.

## 검색 범위

파일 경로 목록과 메시지 기반 로컬 검색 후 모델이 추가 검색어·파일을 선택한다.
도구 실행은 Python이 맡으며 모델에게 임의 셸 실행 권한을 주지 않는다.
숨김 파일, 알려진 인증 파일, credential/token/password 등의 파일명, 심볼릭 링크는 제외한다.
최대 2,000개 파일을 목록화하고, 단계별 증거는 최대 8개 파일·각 8,000자로 제한한다.
누락·잘림은 자료가 없다는 근거로 해석하지 않는다.

### 대화 기록 참고

DM 모드에서는 각 워커가 자기 사용자 토큰으로 같은 원문 DM의 `conversations.history`를 읽는다.
송신자는 준비·추가 답변 단계, 수신자는 해석 단계에서 읽는다. 원문보다 앞선 최근 14일 안의
메시지 최대 30개를 오래된 순으로, 합계 약 6,000자까지 `slack:dm-history` 근거 하나로 넣는다.
현재 원문, 봇 메시지(`bot_id`), 시스템 메시지(`subtype`), 두 참여자 외 작성자는 제외한다. 나에게만 표시 메시지는
Slack 기록에 남지 않는다. 이름 조회 권한을 추가하지 않고 작성자를 `나`/`상대`로 표시하며,
멘션은 읽을 수 있는 이름으로 바꾼다. 대화 내용은 근거 자료일 뿐 지시로 취급하지 않는다.

대화 기록은 로컬 모델 입력에만 쓰고 중앙에 원문을 보내지 않는다. 상대에게는 송신자 승인 흐름이나
수신자 자신의 설명을 통해서만 반영된다. 읽은 개수는 로컬 감사 기록(`history`)에 남긴다.
Home의 **대화 기록 참고**(기본 켬)를 끄면 읽지 않는다. 권한 부족·API 오류는 `history_failed`로
기록하고 작업은 계속한다.

웹 검색을 켰다면 사용자가 허용 폴더의 `public-web-queries.txt`에 작성한 **공개용 검색어** 중
모델이 하나를 선택할 수 있다. 로컬 문서나 사용자 메시지에서 만든 임의 검색어는 외부에 보내지 않는다.
DuckDuckGo 검색 페이지와 최대 두 공개 HTTPS 페이지를 읽는다. 비공개 IP, 인증 포함 URL,
별도 포트, 리다이렉트는 제외하고 확인한 IP로 연결한다. 검색 차단·네트워크 실패는 로컬 감사
기록에 남기고 로컬 자료로 계속 진행한다. 웹이 항상 성공한다고 가정하지 않는다.

## 저장·권한

| 위치 | 내용 |
|---|---|
| 로컬 0700 상태 디렉터리 / 0600 파일 | 전체 초안, 선택한 자료·도구·대화 기록 조회 기록, 직접 Slack 전송 대기열 |
| 중앙 SQLite `workflows` | 원문, 원문 DM 참조, 상태, 초안 해시·버전, 승인한 내용, 공유한 Agent 대화 |
| 중앙의 수신자 전용 필드 | 자기 사용자 확인 답변, 수신자 설명. 송신자 조회·알림에서 제외 |
| Slack | 사용자에게 표시하기로 한 미리보기·설명·설정·기록 |

미리보기는 Slack으로 전송된다. 사용자가 수정 버튼을 누르면 Slack 상호작용 payload의
미리보기가 커넥터 메모리를 일시 통과해 편집창에 들어간다. 나에게만 표시 메시지의 상호작용에는
원 메시지가 포함되지 않으므로, 워커가 이미 화면에 보인 미리보기를 수정 버튼 값(2,000자 이내)에
함께 담는다. 이보다 긴 초안은 빈 편집창이 열리며 미리보기를 복사해 수정한다.
중앙에서 초안을 가져오는 경로는 만들지 않는다. 커넥터·중앙 DB는 승인 전 본문을
저장하지 않는다. 수정창에서 **승인·전달**을 눌러 제출한 최종 본문만 중앙에 저장한다.
이는 Slack이나 서버 운영자가 기술적으로 읽을 수 없는 종단간 암호화를 뜻하지 않는다.

Agent 토큰은 자기 작업을 가져오고 처리하지만 사용자 승인 API를 호출할 수 없다.
사용자 승인은 Slack 커넥터가 실제 상호작용 사용자·워크스페이스·작업·버전을 확인해 전달한다.
승인하지 않은 초안, 다른 버전의 초안, 사용자 수정본과 다른 본문은 publish 단계에서 거절한다.
자동 답변도 중앙에서 기존 공유 내용의 연속 인용인지 검증한다.

## 기존 설치 업데이트

중앙과 양쪽 워커를 함께 전환하는 체크리스트는 [V2_ROLLOUT.md](V2_ROLLOUT.md)를 따른다.

### 원격 요청 절감

원격 워커의 기본 작업 대기는 180초다. `/v2/work/claim?include_requests=true`가 작업과
로컬 감사 요청을 함께 기다려, 별도 `/v2/worker/requests` 반복 조회를 하지 않는다.
감사 요청은 대기 중에도 약 1초 간격의 서버 내부 검사로 감지한다. 감사 요청을 먼저 처리할
때에는 모델 작업의 리스를 잡지 않는다. 기존 v2 클라이언트용 응답 형식과 조회 API는 유지한다.
업데이트한 워커는 업데이트한 중앙 서버 이후에 시작해야 한다.

원격 워커 한 대가 작업 없이 연속 대기한다면 약 182초당 요청 1개, 30일 약 14,242개다.
작업 처리·설정 조회·승인·감사 기록·재시작·상태 점검 요청은 별도이며, 여러 원격 워커의
요청량은 합산된다. 이 계산은 무료 한도나 과금 방지를 보장하지 않는다.
중앙 머신의 워커는 `http://127.0.0.1:8765`를 사용해 ngrok을 경유하지 않는다.

### 전환 순서

1. 기존 작업을 끝내고 양쪽 워커를 잠시 멈춘다. 구버전 작업 테이블은 삭제하지 않는다.
2. 중앙 머신과 두 워커 머신에서 최신 `main`을 받고 `uv sync --locked`를 실행한다.
3. Slack 앱 관리 화면의 manifest를 저장소 `slack-manifest.json`으로 갱신한다.
   Home, `app_home_opened`, bot/user `message.im`, bot/user `im:read`, `im:history`가 추가된다.
   원문 DM 안의 나에게만 표시 메시지(user `chat:write`)와 대화 기록 참고(user `im:history`)는
   이 manifest의 권한·이벤트로 충분하며 추가 변경은 없다. 이름 조회(`users:read`)는 쓰지 않는다.
   변경 권한은 워크스페이스에서 재설치·승인한다. 새로 발급되는 사용자 토큰은 각 소유자의
   로컬 env에만 저장한다. 다른 사람의 토큰으로 대신 실행하지 않는다.
4. 중앙에서 `tacit-server restart`. `/health`의 `protocol: 2`와 Socket Mode 연결을 확인한다.
   Slack 커넥터가 자신의 bot user ID를 등록한 뒤 워커를 시작해야 한다.
5. 각 워커를 다시 시작한다. CLI가 protocol 2를 감지하면 새 워커를 선택한다.
6. Slack Home을 열어 예제 폴더와 실행기를 확인하고 아래 실제 시나리오를 진행한다.

protocol 1 서버에서는 기존 워커로 연결되며 승인 UI가 없다는 경고를 남긴다.
기존 `/v1` API와 `exchanges` 테이블은 이전 작업·구버전 호환을 위해 보존된다.
새 Slack 커넥터는 `/v2`로만 새 작업을 만든다. 두 프로토콜의 미완료 작업은 서로 인계하지 않으므로
업데이트 전에 이전 작업을 완료하고, 과거 작업은 기존 `/v1` 기록으로 확인한다.

## 검증 상태와 실제 실험

통합 브랜치의 추가 검증: `pytest -q` 107개 통과, `ruff check`와 Git 공백 검사 통과.
연결 감시, 유휴 180초 단일 요청, 감사 요청의 대기 깨우기·소유자 격리, 대화 판별 실패 시
비전송, v2 권한 검사, 모의 worker의 DM/Agent 전용 양방향 승인 흐름을 포함한다.
운영 v2 배포·실제 승인 왕복은 아직 완료하지 않았다. 현재 상태는 [배포 문서](V2_ROLLOUT.md)를 참고한다.

2026-09-21 최종 자동 검사: `uv run --no-sync pytest -q` 84개 통과,
`ruff check` 및 Git 공백 검사 통과. 기존 59개에 승인·권한·검색·UI 경로 25개를 추가했다.

자동 테스트는 승인 전 비전송, 수정본 고정, 취소, 잘못된 사용자·버전·리스,
최대 2왕복, 새 정보 재승인, 수신자 정보 비노출, 요청 중복, broadcast, 로컬 범위,
재시작 후 미리보기 재전송, 웹 검색어 제한과 비공개 주소 차단을 확인한다.
이는 실제 Slack·모델·상대 워커 검증의 대체물이 아니다.

실제 실험 순서는 [WORKFLOW_V2_SCENARIOS.md](../demo/WORKFLOW_V2_SCENARIOS.md)에 있다.
2026-09-21 개발 시점에는 중앙 서버 protocol 1과 이 머신의 기존 Kiro 워커 연결을 확인했다.
중앙 머신 SSH·운영 자격증명은 이 머신에 없어 원격 업데이트를 실행하지 않았다.
새 Slack 승인 버튼, 신규 권한, v2 모델 왕복, 상대 알림은 운영 업데이트 후 실검증할 항목이다.
재용씨 수업 중 답장을 성공 근거로 요구하거나, 다른 사용자의 승인 버튼을 대신 누르지 않는다.

Slack 재시도는 결정적 메시지 ID와 로컬 전송 대기열·중앙 확인 기록으로 줄인다.
Slack이 메시지를 수락한 직후 응답이 끊기는 구간의 정확히 한 번 전송까지 보장하지 않는다.
