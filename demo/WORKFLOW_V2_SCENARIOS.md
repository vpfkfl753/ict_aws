# v2 실제 실험: 사람 대화에 숨어 있는 비교 조건 전달하기

이 문서는 양쪽이 상황을 이해하고 진행하는 실험 안내다. 미리 설명받지 못한 사람의 반응은
제품 성능의 증거로 쓰지 않는다. 실제 Tacit Slack 명령·중계·각자 워커로 실행한다.

## 준비

- 중앙 `/health`는 protocol 2, Slack manifest와 사용자 권한은 업데이트되어 있어야 한다.
- 성원: 이 저장소 `examples/bob`, Kiro. 재용: `examples/alice`, 본인 실행기.
- 실제 연구 폴더·대화 기록을 자료 폴더에 넣지 않는다. 테스트 문서는 합성 예제다.
- 재용씨가 수업 중이면 질문·안내 DM만 남기고 사람 승인·답변 단계는 대기한다.

## 1. 최초 승인과 조건 차이

성원이 사람 DM에서 다음 명령을 실행한다.

```text
/tacit-send @이재용 [예제 실험] B24/p3에서 +2%p인데 B17/p2 조건과 직접 비교해도 될까요?
```

기대 동작:

1. 사람 DM 원문은 바로 전달된다. 맥락 작성 중이어도 원문을 기다리지 않는다.
2. 성원의 Tacit 대화에 B24/p3, 자료 파일, 확인되지 않은 사항을 포함한 공유 미리보기가 나온다.
3. 승인 전 중앙에는 원문·상태·초안 해시만 있고 초안 본문은 없어야 한다. 상대에게 맥락이 전달되지 않는다.
4. 성원이 승인하면 재용 Agent가 B17/p2 쪽 자료와 비교한다. 필요하면 추가 질문한다.
5. Agent 질문·답변은 작업 스레드에 보이고, 재용에게 자기 기준에 맞춘 설명이 나온다.

기록: 작업 ID, 실행기, 실제 상태 전이, 승인 버전, 공유 내용, 질문 횟수, 최종 설명과 근거.

## 2. 수정과 취소

같은 예제로 두 작업을 각각 만든다.

- 첫 작업은 미리보기의 일부 문장을 삭제한 뒤 `수정·제외 후 승인`한다.
  수신 Agent와 중앙 공유 기록에 삭제된 내용이 없어야 한다.
- 두 번째는 `취소`한다. 사람에게 이미 간 원문은 그대로 두고 추가 맥락이 전송되지 않아야 한다.
- 처리한 예전 승인 버튼을 다시 눌러도 새로운 공유나 상태 변경이 생기지 않아야 한다.

## 3. 새 정보 추가 승인과 사용자 확인

상대 Agent가 공유된 내용만으로 답하지 못할 질문을 해야 이 경로가 실행된다.
모델이 충분하다고 판단하면 강제로 질문을 만들었다고 기록하지 않는다.
추가 질문이 발생한 경우 다음을 확인한다.

- 이미 승인한 맥락의 답이면 해당 부분을 인용해 자동 답변한다.
- 새 자료가 필요하면 새 공유 미리보기가 뜨며 승인 전 상대에게 전송되지 않는다.
- 추가 질문이 2왕복을 넘지 않는다.
- 그래도 부족하면 자기 사용자에게 물어보고 그 작업만 대기한다. 다른 작업은 진행된다.
- 사용자가 답하면 설명이 이어지되 미확인 내용을 사실로 만들지 않는다.

## 4. Agent 전용 질문과 자동 수신

Tacit 앱과의 대화에서 `/tacit-send @이재용 [예제 실험] baseline 정의가 무엇인가요?`를 실행한다.
사람 간 DM에는 새 원문이 없어야 하고, 승인 후 상대 Agent로 전달된다.
상대가 자기 새 정보를 포함한 답변을 승인하면 질문한 사람의 Tacit 대화에 자동 표시되어야 한다.
`@broadcast`는 등록된 각 상대별 작업·승인을 만든다.
현재 두 명이면 받는 Agent는 한 명뿐이다.

## 5. Slack 설정과 감사

Home에서 `자동 수신`을 끄고 수신 결과가 `/tacit-receive`로만 조회되는지 확인한다.
Home의 기록과 작업 스레드에서 실제 공유 내용·순서를 확인한다.
`내 로컬 접근·도구 기록 받기`로 자기 머신의 검색·읽기 기록을 받는다.
다른 사용자의 로컬 초안이나 접근 기록은 보이지 않아야 한다.

웹 기능은 공개 검색어 파일과 웹 토글을 설정한 경우에만 수행한다.
자동 DM 준비는 신규 권한을 승인한 뒤 켜고, 사람이 보낸 신규 DM을 기준으로 검증한다.
앱이 보낸 원문을 다시 수집해 무한히 작업을 만들지 않는지 확인한다.

## 결과 기록 원칙

`코드 테스트 통과`, `운영 배포 완료`, `실제 모델 응답`, `상대 화면 확인`은 각각 별도 상태다.
이번 시나리오 문서 자체는 실행 결과가 아니다. 아직 실행하지 않은 항목을 성공으로 기록하지 않는다.
